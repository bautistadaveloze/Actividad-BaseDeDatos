01 · Arquitectura

Un programa, varias máquinas

Spark divide un trabajo grande en tareas y las coordina sobre un clúster.

Qué es: un motor de procesamiento distribuido, no una base transaccional.

  • Driver: planifica el trabajo y reúne los resultados.
  • Cluster manager: asigna recursos para la aplicación.
  • Worker: máquina que aporta recursos de cómputo.
  • Executor: proceso que ejecuta tareas y puede guardar datos en memoria.

En la actividad: proyector = driver; celulares = executors simulados. No son máquinas Spark reales.

03 · Machine learning

MLlib + K-Means

MLlib ofrece algoritmos de aprendizaje automático que Spark puede ejecutar sobre datos distribuidos.

  1. Asignar: cada executor acerca sus puntos al centroide más próximo.
  2. Resumir: cada partición calcula sumas y cantidad por grupo.
  3. Reducir: el driver combina resúmenes y mueve los centroides al promedio.
  4. Repetir: comienza otra iteración hasta que los centros dejan de cambiar.

La actividad web deja ver una iteración y comparar qué datos se envían al driver.

04 · Cuándo conviene

Spark y una base relacional se complementan

No son reemplazos directos: cada tecnología encaja mejor con una carga de trabajo distinta.

Apache Spark

Analizar mucho junto

  • Transformar millones de eventos
  • Calcular agregados por lotes
  • Preparar datos o entrenar modelos
Base relacional

Registrar y consultar operaciones

  • Leer o actualizar filas puntuales
  • Mantener transacciones
  • Aplicar restricciones de integridad

Ejemplo: la base registra ventas; Spark analiza millones de ventas y segmenta clientes.
